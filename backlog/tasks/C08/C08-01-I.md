2. Required failure behavior: A crash during registration does not leave permanent online presence.
3. Respect invariant: Presence is advisory; losing RTDB connectivity alone never changes a score. Rejoining uses latest server version.
4. Use the component ports `publishPresence; mirrorPresence; resumeMatch; expireGrace` and data scope: RTDB connections/{uid}/{connectionId}; Firestore presence projection; reconnect token.
5. No credentials, raw player recordings, unlicensed media, hidden answer keys, or personal data enter logs/public fixtures.
6. Every assigned verification command actually runs and passes; missing tools/tests are blocked, not skipped-success.
7. Commit only owned paths and report evidence, changed files, risks and any unresolved dependencies.
