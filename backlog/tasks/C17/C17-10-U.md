## Acceptance criteria

1. Demonstrate the outcome above using a concrete fixture and externally visible result.
2. Required failure behavior: Mute preference does not silence required cue audio.
3. Respect invariant: Host text cannot mutate game state; fallback lines and device/prerecorded speech are always available. Muse is not a TTS service.
4. Use the component ports `renderHostEvent; getHostLine; playHostLine; cancelHostLine` and data scope: Versioned line templates; optional Spark text; client speech settings; no celebrity voice clone.
5. No credentials, raw player recordings, unlicensed media, hidden answer keys, or personal data enter logs/public fixtures.
6. Every assigned verification command actually runs and passes; missing tools/tests are blocked, not skipped-success.
7. Commit only owned paths and report evidence, changed files, risks and any unresolved dependencies.
